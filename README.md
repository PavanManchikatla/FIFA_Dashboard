# WC26 Continental Chaos Board

A live, funny, interactive 3D dashboard for the 2026 FIFA World Cup with a real ML
win-probability engine. Infrastructure cost target: **$0/month**.

See [PLAN.md](PLAN.md) for the architecture / data contracts / phased roadmap and
[CLAUDE.md](CLAUDE.md) for the working rules.

## Status

- ✅ **Phase 1 — Foundation**: monorepo scaffold, tile-broker + holo MapLibre style, `HoloMap`
  with live beacons fed by `/api/live` (wc26ir → cache, cache-aside + CDN-edge cached),
  template ticker. Real wc26ir + Upstash wired; public deploy (Vercel) postponed to post-phases.
- ✅ **Phase 2 — Oracle core**: Python ML — ingest (martj42) → Elo → Dixon-Coles + GBM blend →
  walk-forward backtest (accepted, beats Elo-only 3/4). Publishes `ratings.json`,
  `match_probs.json`, `meta.json`.
- ✅ **Phase 3 — Simulator + Oracle page**: 48-team Monte Carlo (`simulate.py`, exhaustive
  bracket tests) → `simulation.json` + `insights.json`; `/oracle` page with champion-odds bars,
  group heat tables, Bracket-of-Doom survival heatmap, and the honest model card.
- ✅ **Phase 4 — Live layer**: `/api/winprob` analytic in-match win prob (remaining-time Poisson
  on published Dixon-Coles λ); `/match/[id]` with the heartbeat chart + Panic Index gauges;
  goal-event beacon flash on the map; Oracle insights wired into the ticker.
- ⬜ Phase 5 — Polish (HoloLattice, cross-fade, SSE, OG cards)

## Pages

- `/` — landing (links into the map and the Oracle).
- `/map` — holo hybrid MapLibre map: 16 stadium beacons (amber when a match is live),
  multi-provider tile failover, template-driven ticker.
- `/oracle` — the Oracle: champion-odds bars, group heat tables, Bracket-of-Doom survival
  heatmap, model card. Server-rendered from the committed `public/oracle/*.json`.
- `/match/[id]` — live in-match win prob, heartbeat chart, and Panic Index gauges.

## Architecture / data flow

```
worldcup26.ir ──(server only)──> lib/sources/wc26ir.ts ─> normalize ─> Upstash cache
                                                                          │
browser ──> /api/live (cache-aside, CDN edge cached) <─────────────────────┘
browser ──> public/oracle/*.json  (built by the ML pipeline, imported via lib/oracle.ts)

ml/  (offline, GitHub Actions):
  ingest(martj42) → elo → features → goals_model(DC + calibrated GBM) → simulate(10k) →
  insights → publish → public/oracle/{ratings,match_probs,simulation,insights,meta}.json
```

The browser never calls an external API. All external data flows through the server poller →
Redis, or the committed ML JSON. See [PLAN.md](PLAN.md) §2–§6 and [CLAUDE.md](CLAUDE.md).

## Quick start (web)

```bash
cd apps/web
npm install
npm run dev          # http://localhost:3000
# scripts: npm run lint | npm run typecheck | npm test | npm run build
```

With no env set, the app runs fully on in-process mocks (Upstash → Map fallback, wc26ir →
`mocks/` fixtures, `MOCK_LIVE_GOALS=1` to tick a live match, OpenFreeMap keyless tiles).
Copy `apps/web/.env.example` to `.env.local` to wire real services (`WC26IR_*`, `UPSTASH_*`,
`CRON_SECRET`, `NEXT_PUBLIC_STADIA_KEY`/`_MAPTILER_KEY`). See [docs/DEPLOY.md](docs/DEPLOY.md).

## ML pipeline

```bash
cd ml
uv run --extra dev pytest          # unit + bracket-rule + backtest-helper tests
uv run python -m wc26ml.ingest     # download + clean martj42 → ml/data/ (gitignored)
uv run python -m wc26ml.backtest   # walk-forward acceptance gate (exits non-zero if rejected)
uv run python -m wc26ml.publish    # writes public/oracle/*.json (runs the backtest model card)
```

`ml/data/` is gitignored (regenerated by `ingest`); the committed model outputs are the
`public/oracle/*.json` artifacts the web app consumes.
